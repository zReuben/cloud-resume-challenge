Multi-Account + CI/CD Promotion Pipeline

Build once, promote safely across ENG → TEST → PROD

GitHub ← Back to home

After completing the Cloud Resume Challenge, I wanted to expand into a more professional setup. Testing changes directly on my live site felt unrealistic, so I built a multi-account, multi-environment CI/CD pipeline. This approach mirrors how real teams work: build once, save artifacts, and promote them safely through ENG → TEST → PROD with approvals and fast rollbacks.

Pipeline design

Build workflow

  • Triggered on pushes to main.
  • Runs unit and integration tests (no AWS access yet).
  • Packages backend SAM template + frontend bundle into a single artifact.
  • Saves the artifact in S3 for promotion.

Deploy workflow

  • Uses the same artifact in each environment (ENG → TEST → PROD).
  • Approvals required before promoting to TEST or PROD.
  • Configuration comes from SSM Parameter Store and stack outputs.

Rollback

Rollbacks target a specific environment and commit SHA. The workflow skips rebuilding, redeploys the saved artifact, restores the site if needed, and invalidates CloudFront. Recovery takes about one minute.

Operational notes

  • Speed: Full ENG → PROD pipeline completes in ~10–15 minutes.
  • Safety: TEST is a clean dress rehearsal before PROD.
  • Efficiency: Artifact S3 bucket has a 60-day lifecycle to avoid growth without losing current versions.
  • Security: GitHub OIDC + IAM roles, no long-lived keys, Vault for secret handling.

What I learned

  • Splitting build vs deploy workflows makes pipelines clearer and safer.
  • Immutable artifacts with approvals are key to reproducibility.
  • Rollback workflows reduce downtime from hours to minutes.
  • Hands-on experience with multi-account AWS setups gave me confidence beyond the basics.
